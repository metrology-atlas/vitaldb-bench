# Analysis scripts

The scripts in `tools/` produced the tables and figures of the timing audit. They are scripts, not part of
the installed package: run them as `python tools/<name>.py` after `pip install -e ".[tools]"`. Each one's
docstring gives its commands and says what it reads and writes; per-case output stays on the analysis
machine. See [Reproduce the results](../how-to/reproduce-results.md) for which made which file.

This page is generated by `tools/gen_tools_page.py`.

| `abp_validate.py` | Does the ECG-PPG correction hold up against the arterial pressure? Per-case numbers, this machine only. |
| `art_check.py` | Arterial pressure as a second timing reference for the ECG-PPG delay. Per-case numbers only. |

| `art_pre_event_plot.py` | Event-locked examples: ART per minute (SBP, MAP, DBP) and cuff readings from 60 min before to 30 min after single flushes/zeroings. Args: artmin.jsonl nibp.jsonl events.jsonl out.png case:t[:title] ... |
| `art_pre_event_trends.py` | Trends leading up to arterial-line flushes and zeroings, event by event. This machine only; aggregates and figures leave. |
| `art_zero_jumps.py` | Arterial pressure before and after line accesses, to find recalibration jumps at zeroing. Per case, this machine only; aggregates leave. |
| `art_zero_labels.py` | Zeroing labels from tools/art_zero_jumps.py output. This machine only. |
| `art_zero_plot.py` | Figure for art_zero_jumps: pressure changes across line accesses against controls; open-to-air readings. |
| `art_zero_plot2.py` | Figure for art_zero_jumps with 20 s windows: diastolic and pulse pressure (SBP - DBP) change across accesses, and pulse duration (width of the pulse at 50% height) against pulse pressure change. |

| `bis_index_delay.py` | Link S of the timing graph: how the BIS index responds in time to its own EEG. This machine only; aggregates leave. |

| `device_map_figure.py` | Conceptual figure: VitalDB devices and the timing relationships measured between them (aggregates only). |
| `drug_effect_latency.py` | Sanity check of the clocks of devices with no shared signal (Orchestra pumps, FMS rapid infuser, Invos): is the time from an infusion event to its physiological effect plausible? Per case, this machine only. |
| `eeg_cardiac_recheck.py` | Recheck of the cardiac artefact in BIS EEG with the SNUADC/BIS offset known. The first pilot (eeg_sync_pilot) averaged the EEG -0.3..+0.5 s around each R peak on raw stamps, but the same event is stamped ~0.8 s earlier in BIS, so an artefact would have fallen outside that window. Here both devices are on the stamp-model times (as tools/sa_corrected.py, variant model) and the R-triggered average spans -2..+1 s. Per case, three 10-min windows: peak-to-noise of the average, its lag, single-beat SNR; and the case's burst-measured EEG-ECG offset for comparison. Aggregates only leave this machine. |
| `eeg_sync_pilot.py` | Can heartbeats in the BIS EEG synchronise it with the ECG? Pilot, per case, this machine only. |
| `emr_markers.py` | EMR anaesthesia start/end against device markers (experiments 1 and 4). Per case, this machine only. |
| `fid_res.py` | Effective temporal resolution of ECG and PPG fiducials in VitalDB (Ruffolo et al. 2025, section 3.3). |
| `flush_response_labels.py` | Flush-response labels from tools/flush_ringing.py output. This machine only. |
| `flush_ringing.py` | Fast-flush (square-wave) response of the arterial line at every flush release. Per case, this machine only. |
| `flush_ringing_plot.py` | Figure for flush_ringing: example releases, damping coefficient vs natural frequency, and within-case trend of the natural frequency. Args: full_fr.jsonl root out.png |
| `foot_export.py` | PPG foot (intersecting tangent) for every exported beat, and the SNUADC port. This machine only. |
| `frame_an.py` | The 30 Hz PPG frame clock, seen through raw-sample PPG fiducials. Per-case numbers only. |
| `gapdist.py` | Gap and overlap distribution of waveform tracks, as each database stores them. Aggregates only. |
| `gen_tools_page.py` | Write docs/reference/tools.md: every script in tools/ with the first paragraph of its docstring. |
| `grid_mode.py` | Experiment: a constant-rate, phase-anchored sawtooth per recording, checked against arterial pressure. |
| `lab_draw_labels.py` | Estimated blood-draw times for VitalDB lab samples, from arterial-line accesses. This machine only. |
| `lab_steps.py` | Do arterial-line events and timing steps line up with blood-draw times? One case, this machine only. |
| `line_access_scan.py` | Arterial line accesses (lineaccess) in VitalDB cases, matched to lab results. This machine only. |
| `loop_closure_art.py` | Loop-closure test for arterial pressure measured three ways: SNUADC ART, EV1000 ART_MBP and CardioQ ABP. Per case, this machine only; aggregates leave. |
| `measurement_export.py` | Per-case PAT measurement records (physiosync.pat_measurement_model) and timing-quality labels. |
| `nibp_plot.py` | Figure: intervals between NIBP readings (with and without an arterial line) and ART vs NIBP agreement. |
| `nibp_scan.py` | Non-invasive blood pressure (Solar8000 NIBP) readings in VitalDB, and their agreement with the arterial line. Per case, this machine only; aggregates leave. |
| `numeric_delay_labels.py` | Per-case numeric delays and the HR delay group, as label CSVs for the AtriumDB label pass. This machine only. |
| `numeric_delay_variability.py` | Are the numeric delays fixed? Per case and per 30-min block, with the algorithm held fixed. This machine only. |

| `numeric_derivation_agg.py` | Aggregate tools/numeric_derivation_pilot.py output across cases (aggregates only). |
| `numeric_derivation_pilot.py` | How are the monitor numerics derived from their waveforms? Pilot, per case, this machine only. |
| `numeric_derivation_plot.py` | Plot the numeric-derivation pilot summary (tools/numeric_derivation_agg.py output; aggregates only). |
| `numeric_intervals.py` | Time between values of the waveform-derived numerics in VitalDB. Aggregates only. |
| `numeric_intervals_plot.py` | Plot tools/numeric_intervals.py output (aggregates only). |
| `numeric_window_diagram.py` | Schematic of the timing model used in tools/numeric_derivation_pilot.py (no data; illustrative numbers). |
| `pair_timing_budget.py` | Timing budget for combining two or more VitalDB time sources (aggregates only; no data read). |
| `pairing_check.py` | Beat pairing by inter-beat-interval matching (physiosync.pair_beats, on hrvmatch) against the old most-common-delay rule (physiosync.match_beats), on the benchmark stretches. Per-case numbers, this machine. |

| `pat_res.py` | Effective time resolution of SNUADC ECG and PLETH, and the PAT sawtooth measured beat by beat. |

| `pause_char.py` | Where and how the ECG-PPG sawtooth stops. Per-case numbers only. |
| `ppg_fix_check.py` | Check physiosync's ECG-PPG delay correction on VitalDB cases. Per-case numbers only. |

| `rate_constancy.py` | Is the sawtooth's slope constant per setup, per case, or only per tooth? Could adjacent teeth share one label? |
| `ref_bench.py` | Does the arterial pressure reference improve the ECG-PPG sawtooth correction? Aggregates only. |

| `setup_offsets.py` | One hardware delay per recording setup, from the per-recording records of a first pass. |
| `shared_artifacts.py` | Shared artefacts as timing references between VitalDB devices and channels. Feasibility check, per case, this machine only (per-case output stays here; only aggregates are reported). |
| `spo2_event_agg.py` | Aggregate tools/spo2_event_pilot.py output (aggregates only). |
| `spo2_event_pilot.py` | SpO2 / PLETH_HR latency from step events in the PLETH waveform. Pilot, per case, this machine only. |
| `spo2_event_plot.py` | Plot the SpO2 step-event pilot summary (tools/spo2_event_agg.py output; aggregates only). |
| `sync_figures.py` | Redraw the clock re-synchronisation figures for the drift document, from the per-case rows that ``syncanalyze.py --stage collect`` cached (this machine only) and its per-case drift table. |

| `t30_gaps.py` | Do AtriumDB's waveform intervals match the real gaps in the source? Aggregates only. |
| `t30_measure.py` | Size and index measurements of one test build, without opening either SDK. |
| `t30_report.py` | Collect the 30-case test matrix results into one table (aggregates only). |
